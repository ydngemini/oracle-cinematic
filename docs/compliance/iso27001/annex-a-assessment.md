# ISO/IEC 27001:2022 Annex A: control assessment

> **DRAFT, needs owner approval.** Version 0.1, 2026-10-14. Pinned at `e3ea107` (branch `worktree-agent-a2ef6defdc1276a4f`).
> This is a gap assessment of the repository and the ledger. **It is not a certification, an audit opinion or a statement that Neoh conforms to ISO/IEC 27001** (CONTRACT C12). Only an accredited certification body can certify, after a Stage 1 and a Stage 2 audit of an ISMS that is already operating.
> The table gives control numbers and short titles only. It does not reproduce the standard's text.
> Statement of Applicability: [statement-of-applicability.md](statement-of-applicability.md).

**Scope assumed:** the Neoh SaaS. That is the repository, the GitHub Actions CI/CD and the DigitalOcean **staging** app `neoh-staging`. No production environment exists (LEDGER L19-02). The owner's workstation is in scope because it holds the source, the secrets and the development database.

**People:** Neoh is a one-person company. The owner is top management, the ISMS owner, the only developer-reviewer, the only operator and the only incident responder. AI coding agents write code under CONTRACT.md. Wherever ISO expects segregation of duties, this assessment says that plainly and names a compensating control.

**Evidence rule:** "implemented" means the control is backed by `path:line`, a ledger row or a test that was read at `e3ea107`. "Implemented" never means production-proven: `production_verified` count = 0 (LEDGER summary). Evidence from staging is marked "staging".
